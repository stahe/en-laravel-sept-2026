    4. The View and Its Model

    Up to this point, actions have generated their own responses: text, JSON, and a few HTML tags written as a string of characters. In a MVC application, this is the role of a view: a file that describes the page HTML, with placeholders for the data passed to it by the action—the view’s model.

    [Laravel] comes with its own view engine, [Blade]. A [Blade] view is a file whose name ends with [.blade.php], stored in the application’s [resources/views] folder. It is a text file—in this case, HTML—in which three types of tags are interpreted on the server:

    • [{{ expression }}]: the value of a [PHP] expression, inserted into the page;
    • [@instruction]: a directive: condition ([@if]), loop ([@foreach]), template inheritance ([@extends], [@section]), inclusion ([@include])... A directive begins with [@], followed by its name;
    • [{{-- commentaire --}}]: a comment, which does not appear on the generated page.

    Everything else is copied as-is. Expressions are written in [PHP]: there is no second language to learn. [Blade] thus resembles [Razor], the view engine of [ASP.NET Core MVC], which also mixes HTML and code, and which also uses the character [@]; it differs from [Thymeleaf] ([Spring MVC]), whose views are valid HTML files enriched with [th:] attributes. A [Blade] view is not executed as-is: upon its first use, [Blade] compiles it into a standard [PHP] file, stored in [storage/framework/views], which it then reuses as long as the view remains unchanged. We’ll see what this file looks like.

    • Lines 17–20: The action builds the view model. The function ***[date] from *[PHP] formats the current time: [H] for the hours, [i] for the minutes, and [s]** for the seconds;
    • Line 21: The function [view] causes [Blade] to generate the page. [view] returns an object [View], which [Laravel] transforms into a response (of type [text/html]) by generating the page;
    • Line 29: another view, with a different variable ([$nom]). [response()->view(...)] generates a response from a view, using the specified code—in this case, 404—to display a custom error page. The action type [View|Response] means: either a [View] or a [Response];
    • lines 31–35: the same view as the [index] action, but with a different template. This is the benefit of separating actions from views: a single view can be used by multiple actions.

The [@php] block should be reserved for this type of preparation: the calculation normally belongs to the action;
    • line 17: a [null] value is displayed as an empty string. The [??] operator in [PHP] (Example 08) replaces a [null] value with a default value;
    • Lines 19–20: [{{ }}] escapes HTML (2a); [{!! !!}], on the other hand, inserts the value as-is, without escaping it (2b). [{!! !!}] is reserved for HTML generated by the application itself, never for user input;
    • lines 22–26: a condition: [@if], [@elseif], [@else], [@endif], with a [PHP] condition in parentheses. Each block is closed by a [@end...] directive;
    • lines 30–36: a loop [@foreach] ... [@endforeach], which is written as the loop [foreach] of [PHP]. Within it, the special variable [$loop] describes the state of the loop: [$loop->index] (the iteration number, starting at 0), [$loop->iteration] (starting at 1), [$loop->first], [$loop->last] (true on the first and last iterations), [$loop->count] (the number of elements).     • Line 32: the ternary operator for [PHP], [condition ? a : b] (Example 11);
    • line 40: the directive [@forelse] ... [@empty] ... [@endforelse] is a loop in which the block [@empty] is executed if the list is empty. This is simpler than a [@if] that would test the length of the list;
    • lines 43–44: calculated expressions ([$total / $nombre]) and the variables from the [@php] block. The function [number_format] from [PHP] formats a number: two decimal places, a comma as the decimal separator, and a space as the thousands separator. In Example 16, we’ll see a much better way to format numbers and amounts;
    • Line 46: The [->] operator iterates through the objects ([$modele->adresse->ville]), and any [PHP] function can be called: [mb_strtoupper] capitalizes a string (the [mb_...] functions, for *multi-byte*, correctly handle accented characters encoded in UTF-8);
    • line 48: the character [@] is interpreted by [Blade] only at the beginning of a word; in an email address, it is copied as-is. To write a [@] followed by a directive name, it is doubled: [@@if] produces [@if]. Similarly, [@{{ ... }}] produces [{{ ... }}], which is useful when a page contains curly braces intended for a framework [JavaScript].

    A note on comments: [Blade] processes [@php] blocks before comments. A comment containing the word [@php] would therefore be interpreted as the start of a code block, with unexpected results: this is why the comment on line 8 does not include it.

namespace App\Aides;

use Brick\Math\BigDecimal;
use Carbon\CarbonInterface;
use Illuminate\Support\Facades\App;
use Illuminate\Support\Number;

class Formats
{
     // "keyboard" -> "CLAVIER"
    public static function majuscules(?string $texte): string
    {
        return $texte === null ? '' : mb_strtoupper($texte);
    }

     // an amount in a currency, formatted according to the request language (see the
     // FixerLangue middleware): 1149.9 -> "1 149,90 €" in French, "€1,149.90" in
     // English. The intl extension of PHP recognizes the conventions for each country
    public static function monnaie(BigDecimal $montant, string $devise = 'EUR'): string
    {
        return Number::currency($montant->toFloat(), in: $devise, locale: App::getLocale());
    }

     // a date written out in full, in the language of the request: "Saturday, September 26, 2026"
    public static function dateLongue(CarbonInterface $jour): string
    {
        return $jour->locale(App::getLocale())->isoFormat('dddd D MMMM YYYY');
    }
}
    • Lines 14–17: a static method ([static]): it is called on the class, without an object ([Formats::majuscules('clavier')]). It accepts [null];

The class [Number] of [Laravel] is based on the extension [intl] of [PHP], which supports the conventions of all countries (it uses data from the Unicode project *CLDR*): [Number::currency] formats an amount, with the currency designated by its international code ([EUR], [USD]). [Carbon] comes with translations of these names in over two hundred languages. The [CarbonInterface] type accepts all [Carbon] dates.

    public function recherche(Request $request): View
    {
         // string: the parameter, as a string ('' if absent)

            'modele' => new RechercheModele($motCle, $genre, self::GENRES, $resultats),

    public function afficher(): View

    public function traiter(Request $request): View

         // array_keys: the valid VALEURS values for each list (the array keys)
        $validateur = Validator::make($request->post(), [
            'titre' => ['required', Rule::in(array_keys($l->titres()))],

            'langues' => 'array',
            'langues.*' => Rule::in(array_keys($l->langues())),

         // what the browser actually sent, parameter by parameter
        $recu = [];
        foreach ($request->post() as $nom => $valeur) {
            $recu[] = "$nom = [".implode(', ', (array) $valeur).']';
        }
        return view('formulaire.formulaire', [
            'listes' => $l,
            'saisie' => $request->post(),

    4.8. Example 20: The Post/Redirect/Get pattern

    When a POST action returns a page, that page is the result of a POST. If the user refreshes the page (by pressing [F5]), the browser sends the POST request, following a warning that few people read: the command is sent twice, and the message is posted twice. The Post/Redirect/Get pattern (PRG) avoids this problem: a successful POST action does not return a page; it responds with a redirect (example 04) to a page GET, which the browser requests immediately. Reloading this page simply re-executes the GET action.

    One problem remains: the GET page would like to display a message (“the task has been added”), but it is the POST action that knows this message, and it cannot pass a variable to a request that has not yet occurred. The solution: the flash message, stored in the session by the action POST, is retained until the next request, displayed, and then discarded. This is the mechanism that [Laravel] was already using, in Example 19, for form errors.

            $taches = $this->liste();
            $taches[] = $libelle;
             // forever: the value is retained indefinitely
            Cache::forever(self::CLE, $taches);
        });
    }
}

In [PHP], this is impossible: as we saw in examples 01 and 06, nothing survives the query. The list must therefore be stored outside of [PHP]: in a database, a file... or in the cache of [Laravel], which we are using here.

    • Line 18: The [Cache] interface provides access to the application’s cache: a store of key→value pairs. // app/Services/ContactsService.php: contacts, shared by everyone, stored in
// the Laravel cache (see Example 20)

namespace App\Services;

use App\Models\Contact;
use Illuminate\Support\Facades\Cache;

class ContactsService
{
    private const CLE = 'contacts';

     /** @return array{contacts: list<Contact>, dernierId: int} */
    private function donnees(): array
    {
        return Cache::get(self::CLE, [
            'contacts' => [
                new Contact(1, 'Marie Durand', '01 23 45 67 89'),
                new Contact(2, 'Paul Martin', '06 12 34 56 78'),
                new Contact(3, 'Philippe Jandot', '02 98 76 54 32'),
            ],
            'dernierId' => 3,
        ]);
    }

     // a data modification, under a lock: the function receives the data,
     // modifies it (&), and returns the result of the operation
    private function modifierDonnees(callable $operation): mixed
    {
        return Cache::lock('contacts-verrou', 10)->block(5, function () use ($operation) {
            $donnees = $this->donnees();
            $resultat = $operation($donnees);
            Cache::forever(self::CLE, $donnees);
            return $resultat;
        });
    }

     /** @return list<Contact> */
    public function liste(): array
    {
        return $this->donnees()['contacts'];
    }

     // the contact, or null if it does not exist
    public function lire(int $id): ?Contact
    {
        return array_find($this->liste(), fn (Contact $c) => $c->id === $id);
    }

    public function modifier(int $id, string $nom, string $telephone): ?Contact
    {
        return $this->modifierDonnees(function (array &$donnees) use ($id, $nom, $telephone) {
            foreach ($donnees['contacts'] as $i => $contact) {
                if ($contact->id === $id) {
                     // A contact is immutable (read-only): a new one is created,
                     // which replaces the old one in the array
                    return $donnees['contacts'][$i] = new Contact($id, $nom, $telephone);
                }
            }
            return null;
        });
    }

    public function ajouter(string $nom, string $telephone): Contact
    {
        return $this->modifierDonnees(function (array &$donnees) use ($nom, $telephone) {
            $contact = new Contact(++$donnees['dernierId'], $nom, $telephone);
            $donnees['contacts'][] = $contact;
            return $contact;
        });
    }

    public function supprimer(int $id): ?Contact
    {
        return $this->modifierDonnees(function (array &$donnees) use ($id) {
            foreach ($donnees['contacts'] as $i => $contact) {
                if ($contact->id === $id) {
                     // array_splice removes element i from the array and renumbers the subsequent elements
                    array_splice($donnees['contacts'], $i, 1);
                    return $contact;
                }
            }
            return null;
        });
    }
}

    Contacts are stored in the cache, just like the tasks in Example 20. Each contact is an immutable [Contact] object (an ID, a name, a phone number), stored in an array with the most recently assigned ID. A few points about [PHP]:

    • Lines 29–37: All modifications follow the same pattern: acquire the lock, read the data, modify it, write it back, and release the lock. This method writes to the array once; each modification passes a function (of type [callable], “callable”) to it, which receives the data and modifies it. The function must modify the array itself, not a copy: its parameter is declared as [array &$donnees], where [&] specifies a pass-by-reference (without [&], an array is copied; see Example 06);
    • lines 51–63: A contact is immutable: a new one is created, which replaces the old one in the array. An assignment is an expression whose value is the assigned value: [return $donnees['contacts'][$i] = new Contact(...)] replaces the contact and returns it;
    • line 68: [++] placed before a variable increments it by 1 and returns the new value;
    • line 80: [array_splice] removes an element from the array and renumbers the subsequent elements;
    • The methods return [null] for a nonexistent contact: it is up to the controller to decide on the response.

    // Confirmation of forms with the attribute `data-confirmation="..."`
// Without JavaScript, these forms are simply submitted without confirmation.
(() => {
  const modale = document.getElementById('modale-confirmation');
  const message = document.getElementById('modale-confirmation-message');
  let enAttente = null; // The form to submit if confirmation is given

   // 1. We intercept the submission of forms that require confirmation
  document.querySelectorAll('form[data-confirmation]').forEach((formulaire) => {
    formulaire.addEventListener('submit', (evenement) => {
      evenement.preventDefault(); // Sending is suspended
      enAttente = formulaire;
      message.textContent = formulaire.dataset.confirmation;
      modale.classList.remove('d-none'); // The window appears
    });
  });

   // 2. The two buttons in the window
  modale.addEventListener('click', (evenement) => {
    const action = evenement.target.dataset.action;
    if (action === 'oui') {
      enAttente.submit(); // Submit, SANS trigger the 'submit' event again
    } else if (action === 'non') {
      modale.classList.add('d-none');
      enAttente = null;
    }
  });
})();
    • line 3: the code is enclosed in an anonymous function, which is executed immediately; its variables do not interfere with those of the other scripts on the page;
    • lines 4–6: the window, the message location, and the form awaiting confirmation;
    • lines 9–14: for each form that has a [data-confirmation] attribute, the [submit] event—triggered when the form is submitted—is intercepted. [preventDefault()] suspends submission; the form is put on hold, and its message ([dataset.confirmation], the value of the [data-confirmation] attribute) is displayed in the window, which appears;
    • lines 19–25: a single handler for clicks in the window: [evenement.target] is the element clicked; its attribute [data-action] specifies which button it is. “Yes” submits the pending form using the [submit()] method, which—unlike clicking a button—does not trigger the [submit] event (otherwise, the window would reappear); “No” hides the window.

    Without [JavaScript], the form is simply submitted without confirmation: the page remains usable. This is progressive enhancement: [JavaScript] adds convenience, but the application does not depend on it.
