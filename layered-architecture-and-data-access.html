    9. Layered Architecture and Data Access

    The previous examples stored their data in memory or in the cache. A real application stores it in a database and is organized into layers (see the diagram in the introduction):

    • the web layer (controllers, views): read the request, call the business layer, select the view;
    • the business layer: business rules;
    • the DAO layer (*Data Access Object*): database queries.

    Each layer is aware only of the layer below it, and as few details about it as possible: the web layer is unaware of the SQL layer, and the business layer is unaware of the HTML layer. This separation makes each layer easier to understand, test, and evolve. Example 28 applies this to managing a list of people: it is, on a smaller scale, the management of doctors and clients from the case study.

    In [PHP], database access is organized across several layers:

    • the PDO extension (*PHP Data Objects*) of [PHP] defines an interface common to all SGBD modules: opening a connection, executing a SQL command, and reading rows. Each SGBD has its own driver: [pdo_mysql] for [MySQL] (and [MariaDB]), included with [PHP];
    • the query builder (*query builder*) of [Laravel] ([DB] facade) constructs the SQL commands from method calls ([where], [orderBy]...), regardless of the SGBD, and manages connections and transactions;
    • Eloquent, the ORM (*Object-Relational Mapper*) of [Laravel], maps classes (models, as defined by [Eloquent]) to database tables and transforms the retrieved rows into objects. It follows the so-called *Active Record* model: each object knows how to read and save itself ([Personne::find(1)], [$personne->save()]).

    This is the equivalent of converting [JDBC], [JPA], and [Hibernate] to [Java], [Entity Framework Core] to [C#], or [SQLAlchemy] to [Python]. Note a consequence of how [PHP] works: since nothing survives the request, each request opens its own connection to the database (upon its first SQL request) and closes it upon termination. There is no connection pool as in [Java] or [Python]; opening a connection to [MySQL] on the same machine takes only a fraction of a millisecond.

    This example requires a [MySQL] (or [MariaDB]) server to be running: the appendix explains how to install one using [Laragon].

-- The script is written in UTF-8
SET NAMES utf8mb4;
DROP DATABASE IF EXISTS dbpersonnes;
CREATE DATABASE dbpersonnes CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE dbpersonnes;

CREATE TABLE personnes (
  id INT NOT NULL AUTO_INCREMENT,
   -- the row version, incremented with each modification (see layer DAO)
  version INT NOT NULL DEFAULT 0,
  prenom VARCHAR(30) NOT NULL,
  nom VARCHAR(30) NOT NULL,
  age INT NOT NULL,
  PRIMARY KEY (id),
   -- Two people cannot have the same first and last names
  CONSTRAINT unq_personnes_prenom_nom UNIQUE (prenom, nom)
) ENGINE = InnoDB;

INSERT INTO personnes (prenom, nom, age) VALUES
  ('Marie', 'Pélissier', 42),
  ('Jacques', 'Bromard', 35),
  ('Philippe', 'Jandot', 58);
    • Line 3: The script is written in [UTF-8]; this is specified to the server so that the accents in the data ([Pélissier]) remain intact;
    • line 5: the character set [utf8mb4] accepts all characters (accents, emojis, etc.). The [utf8mb4_unicode_ci] collation compares strings without regard to uppercase letters or accents: for [MySQL], [pelissier], and [Pélissier] are equal;
    • line 11: a version number, incremented each time the line is modified (see “optimistic lock,” below);
    • line 17: a named uniqueness constraint: the database does not allow two people with the same first and last names. The name will be used to identify the error.

    [Laravel] can also create the tables itself, using migrations: [PHP] classes that describe, step by step, the creation and modifications of each table (command [php artisan migrate]). // bootstrap/app.php: the application from Example 28

use Illuminate\Database\Events\QueryExecuted;
use Illuminate\Database\Events\TransactionBeginning;
use Illuminate\Database\Events\TransactionCommitted;
use Illuminate\Database\Events\TransactionRolledBack;
use Illuminate\Foundation\Application;
use Illuminate\Support\Facades\DB;
use Illuminate\Support\Facades\Event;

(require __DIR__.'/../../vendor/autoload.php')->addPsr4('App\\', __DIR__.'/../app/');

return Application::configure(basePath: dirname(__DIR__))
    ->withRouting(
        web: __DIR__.'/../routes/web.php',
         // the route used by Bootstrap (see Example 15)
        then: fn () => require __DIR__.'/../../commun/bootstrap.php')
    ->withMiddleware()
    ->withExceptions()
    ->booted(function () {
         // DB_LOG=true (.env file): each SQL command and each step of a
         // transaction is displayed in the server console
        if (env('DB_LOG')) {
            DB::listen(fn (QueryExecuted $q) =>
                error_log($q->sql.' '.json_encode($q->bindings, JSON_UNESCAPED_UNICODE)));
            Event::listen(TransactionBeginning::class, fn () => error_log('BEGIN'));
            Event::listen(TransactionCommitted::class, fn () => error_log('COMMIT'));
            Event::listen(TransactionRolledBack::class, fn () => error_log('ROLLBACK'));
        }
    })
    ->create();
    • Lines 24–30: If [DB_LOG] equals [true], each SQL command is displayed in the console. [DB::listen] registers a function called after each SQL command, with a [QueryExecuted] object (the command text, its parameters, and its duration). [Event::listen] logs a function called for each event of a given type: [Laravel] thus signals, among other things, the start, confirmation, and cancellation of transactions. Events are another way—along with middleware—to intervene in the framework’s operation. (We read [env] directly, for brevity; a typical application would use a configuration file; see Example 25.)

    There is nothing else to configure: the classes of the three layers are created by the [Laravel] container, which injects the layer below into each one (the controller receives the business layer, and the business layer receives the DAO layer).

    <?php
// app/Models/Personne.php: a row in the [personnes] table, an Eloquent “model”

namespace App\Models;

use Illuminate\Database\Eloquent\Model;

// Model: the parent class of Eloquent entities, Laravel’s ORM. The columns
// in the table automatically become properties of the object ($p->name)
class Personne extends Model
{
     // the table name (Eloquent would infer this from the class name: `people`)
    protected $table = 'personnes';

     // the table does not have the columns created_at and updated_at, which Eloquent maintains by default
    public $timestamps = false;

     // the columns that can be filled in bulk: new Person([...]), update([...])
    protected $fillable = ['prenom', 'nom', 'age'];

     // type conversions, column by column
    protected function casts(): array
    {
        return ['age' => 'integer', 'version' => 'integer'];
    }
}
    • Line 10: A model named [Eloquent] inherits from the class [Model]. The table columns are not declared: [Eloquent] reads the row, and each column becomes a property of the object ([$p->nom], [$p->version]). The primary key is, by default, the column [id], generated by the database ([AUTO_INCREMENT]);
    • line 13: the table associated with the class. [Eloquent] would derive it itself from the class name by putting it in the plural (in English);
    • line 16: By default, [Eloquent] maintains two columns, [created_at] and [updated_at], which it assumes are present in every table. Ours does not have them;
    • line 19: the columns that can be filled in “in bulk” from an array ([Personne::create([...])]). This is a precaution: an array from a form might contain other columns ([version], [id]...), which we do not want to be filled in this way;
    • Lines 22–25: Type conversions: the driver converts certain numeric columns to strings; [casts] ensures they are integers. There are conversions for Booleans, dates ([Carbon] objects), decimals, arrays (a JSON column)...

    <?php
// app/Dao/PersonnesDao.php: the DAO layer, queries, no business rules

namespace App\Dao;

use App\Metier\DonneesPersonne;
use App\Models\Personne;
use Illuminate\Database\Eloquent\Collection;
use Illuminate\Support\Facades\DB;

class PersonnesDao
{
     // SELECT * FROM people ORDER BY last name, first name
    public function lister(): Collection
    {
        return Personne::orderBy('nom')->orderBy('prenom')->get();
    }

     // SELECT * FROM people WHERE id = ? LIMIT 1; null if the person does not exist
    public function lire(int $id): ?Personne
    {
        return Personne::find($id);
    }

     // a person with the same first and last name, other than [$saufId]:
     // SELECT * FROM person WHERE first name = ? AND last name = ? AND ID <> ? LIMIT 1
    public function homonyme(string $prenom, string $nom, int $saufId = 0): ?Personne
    {
        return Personne::where('prenom', $prenom)->where('nom', $nom)
            ->where('id', '<>', $saufId)->first();
    }

     // INSERT INTO people (first name, last name, age) VALUES (?, ?, ?) ; the database generates
     // the ID, which Eloquent stores in the object
    public function ajouter(DonneesPersonne $donnees): Personne
    {
        return Personne::create(['prenom' => $donnees->prenom, 'nom' => $donnees->nom,
            'age' => $donnees->age]);
    }

     // the VERROU OPTIMISTE: UPDATE ... SET ..., version = version + 1
     // WHERE id = ? AND version = ? ; returns the number of modified lines (0: the
     // row has been modified or deleted since it was read)
    public function modifier(int $id, int $version, DonneesPersonne $donnees): int
    {
        return Personne::where('id', $id)->where('version', $version)->update([
            'prenom' => $donnees->prenom, 'nom' => $donnees->nom, 'age' => $donnees->age,
             // DB::raw: a SQL expression, written as-is in the SQL order
            'version' => DB::raw('version + 1'),
        ]);
    }

     // DELETE FROM people WHERE id = ?
    public function supprimer(int $id): void
    {
        Personne::whereKey($id)->delete();
    }
}

    The DAO layer contains only queries, with no business logic. Each method uses the connection for the current query and participates in the open transaction, if there is one, initiated by the business layer.

    • Lines 14–17: [Personne::orderBy(...)] initiates a query on the people table; the methods are chained together ([orderBy] adds a sort), and [get()] executes the query. The result is a collection [Eloquent] (example 03) of objects [Personne];
    • lines 20–23: [find]: retrieval by primary key, or [null];
    • lines 27–31: [where(colonne, valeur)] adds an equality condition; [where(colonne, opérateur, valeur)] adds any condition. The values are passed to the database as parameters of the SQL command (the [?] commands), and are never copied into its text, which makes injection via SQL impossible. [first()] returns the first line ([LIMIT 1]) or [null];
    • lines 35–39: [Personne::create] creates the object from an array (within the scope of [$fillable]) and inserts it into the database; [Eloquent] stores the ID generated by the database in the object;
    • lines 44–51: the update, with an optimistic lock. The [UPDATE] command has two conditions: the person’s ID and the version read when the form was displayed. It increments the version by 1: [DB::raw] inserts an expression SQL as-is ([version + 1]), instead of a value. If another query has modified the row in the meantime, its version has changed, and [UPDATE] does not modify any rows: [update] returns the number of modified rows, which is 0 in this case. This is the principle of optimistic locking: nothing is locked, but concurrent modifications are detected. ([Eloquent] does not manage a version number itself, unlike [Hibernate] or [SQLAlchemy]: the condition is written by hand.);
    • lines 54–57: a [DELETE], constructed in the same way ([whereKey]: a condition on the primary key).

    <?php
// app/Metier/PersonnesMetier.php: the MÉTIER layer, the business rules, and they
// alone. Each operation that writes to a TRANSACTION is validated (COMMIT) if the
// function completes normally, rolled back (ROLLBACK) if an exception occurs

namespace App\Metier;

use App\Dao\PersonnesDao;
use App\Models\Personne;
use Exception;
use Illuminate\Database\Eloquent\Collection;
use Illuminate\Database\QueryException;
use Illuminate\Support\Facades\DB;

class PersonnesMetier
{
    private const HOMONYME = 'Une personne porte déjà ces prénom et nom.';

    private const MODIFIEE = 'Cette fiche a été modifiée entre-temps : rechargez-la.';

    private const INCONNUE = "Cette personne n'existe pas (ou plus).";

    public function __construct(private PersonnesDao $dao)
    {
    }

    public function lister(): Collection
    {
        return $this->dao->lister();
    }

    public function lire(int $id): Personne
    {
        return $this->dao->lire($id) ?? throw new MetierException(self::INCONNUE);
    }

    public function ajouter(DonneesPersonne $donnees): Personne
    {
        try {
             // DB::transaction: the function is executed within a transaction
            return DB::transaction(function () use ($donnees) {
                 // Rule 1: No two people can have the same first and last names
                if ($this->dao->homonyme($donnees->prenom, $donnees->nom)) {
                    throw new MetierException(self::HOMONYME);
                }
                return $this->dao->ajouter($donnees);
            });
        } catch (QueryException $e) {
            throw self::traduire($e);
        }
    }

    public function modifier(int $id, int $version, DonneesPersonne $donnees): Personne
    {
        try {
            return DB::transaction(function () use ($id, $version, $donnees) {
                $personne = $this->lire($id);
                 // Rule 2: Do not modify a record that has been modified in the meantime by someone else
                if ($personne->version !== $version) {
                    throw new MetierException(self::MODIFIEE);
                }
                if ($this->dao->homonyme($donnees->prenom, $donnees->nom, $id)) {
                    throw new MetierException(self::HOMONYME);
                }
                 // The UPDATE "WHERE id = ... AND version = ..." did not modify any rows:
                 // Another query has modified the record since it was read
                if ($this->dao->modifier($id, $version, $donnees) === 0) {
                    throw new MetierException(self::MODIFIEE);
                }
                 // the record, read again: its new values and new version
                return $this->lire($id);
            });
        } catch (QueryException $e) {
            throw self::traduire($e);
        }
    }

    public function supprimer(int $id): Personne
    {
        return DB::transaction(function () use ($id) {
            $personne = $this->lire($id);
            $this->dao->supprimer($id);
            return $personne;
        });
    }

     // two simultaneous additions: the database's uniqueness constraint rejected the
     // second one; getMessage() contains the message from MySQL, including the constraint name
    private static function traduire(QueryException $e): Exception
    {
        if (str_contains($e->getMessage(), 'unq_personnes_prenom_nom')) {
            return new MetierException(self::HOMONYME, previous: $e);
        }
        return $e;
    }
}
    • lines 17–21: the business rule messages;
    • lines 32–35: a nonexistent person is a business error. The operator [??] accepts an expression [throw] on the right-hand side: if the person is [null], the exception is thrown;
    • lines 37–51: Rule No. 1: No two people may have the same first and last names. [DB::transaction] executes the function within a transaction: if the function completes normally, the transaction is committed ([COMMIT]), and [DB::transaction] returns the function’s value; if an exception is thrown, the transaction is rolled back ([ROLLBACK]): none of the changes made within the function are retained, and the exception proceeds. The business layer thus determines the scope of transactions: one business operation, one transaction. The rule is checked before writing, and a [MetierException] is raised if it is not followed. But this check is not sufficient: two simultaneous queries could both verify that there is no duplicate, and then both insert the data. The database’s uniqueness constraint then rejects the second [INSERT], and [Laravel] triggers a [QueryException], which the [traduire] method transforms into the same [MetierException]. The database is the last line of defense;
    • lines 53–76: Rule No. 2: Do not modify a record that has been modified in the meantime by someone else. The update form carries the version of the record that was read (in a hidden field); if it differs from the current version, the record has changed since it was displayed. Here again, the database (via the optimistic lock in layer DAO) detects when a concurrent modification occurs between the read operation and the [UPDATE] transaction: the [UPDATE] transaction then does not modify any rows. The record is then read again, with its new values;
    • lines 78–85: The deletion marks the person as deleted for the confirmation message;
    • lines 89–95: [getMessage()] contains the message from [MySQL], including the name of the violated constraint. Another error is returned as-is: this is not a business error, but a programming error. The parameter named [previous] attaches the original exception to the new one for the log.

namespace App\Http\Controllers;

use App\Http\Requests\PersonneRequest;
use App\Metier\MetierException;
use App\Metier\PersonnesMetier;
use Illuminate\Http\RedirectResponse;
use Illuminate\View\View;

class PersonnesController
{
    public function __construct(private PersonnesMetier $metier)
    {
    }

    public function accueil(): RedirectResponse
    {
        return redirect()->route('personnes.liste');
    }

    public function liste(): View
    {
        return view('personnes.liste', ['personnes' => $this->metier->lister()]);
    }

    public function ajout(): View
    {
        return view('personnes.formulaire', ['titre' => 'Ajouter une personne',
            'action' => route('personnes.ajouter'), 'personne' => null]);
    }

     // PersonneRequest: an invalid form does not reach this point (see Example 19)
    public function ajouter(PersonneRequest $request): RedirectResponse
    {
        try {
            $p = $this->metier->ajouter($request->donnees());
        } catch (MetierException $e) {
             // A business rule rejects the form: return to the form, with the entered data and the
             // message at the bottom of the page
            return back()->withInput()->with('erreur', $e->getMessage());
        }
        return redirect()->route('personnes.liste')->with('succes', "$p->prenom $p->nom a été ajouté(e).");
    }

    public function modification(int $id): View|RedirectResponse
    {
        try {
            $p = $this->metier->lire($id);
        } catch (MetierException $e) {
            return redirect()->route('personnes.liste')->with('erreur', $e->getMessage());
        }
        return view('personnes.formulaire', ['titre' => 'Modifier une personne',
            'action' => route('personnes.modifier', $id), 'personne' => $p]);
    }

    public function modifier(PersonneRequest $request, int $id): RedirectResponse
    {
        try {
            $p = $this->metier->modifier($id, (int) $request->validated('version'), $request->donnees());
        } catch (MetierException $e) {
            return back()->withInput()->with('erreur', $e->getMessage());
        }
        return redirect()->route('personnes.liste')->with('succes', "$p->prenom $p->nom a été modifié(e).");
    }

    public function supprimer(int $id): RedirectResponse
    {
        try {
            $p = $this->metier->supprimer($id);
        } catch (MetierException $e) {
             // No form to redisplay: the error is also displayed in a pop-up message
            return redirect()->route('personnes.liste')->with('erreur', $e->getMessage());
        }
        return redirect()->route('personnes.liste')->with('succes', "$p->prenom $p->nom a été supprimé(e).");
    }
}

    In a single transaction, we can see: the read of the master record, the search for a namesake, the [UPDATE], and the re-read. The [UPDATE] increments the version ([version + 1], written as-is thanks to [DB::raw]), and sets the optimistic lock condition ([and version = ?], with the read version, here 1). [Laravel] surrounds table and column names with grave accents ([personnes]), which is how these names are written in [MySQL]. Now let’s submit the same form a second time, still with version 1:
